# 数据分析报告 — 怎么讲故事

数据分析师做完阶段 1-4 之后,**报告本身决定决策者是否能用上这份分析**。烂报告 = 浪费分析。

## 核心原则

### 1. 先观点,后证据

人会读报告但不会读"长篇详尽的脚本输出"。开头 3 句话说清楚:
- 我的结论是什么?
- 这个结论建议谁做什么?
- 有什么前置假设/限制?

### 2. 数字必须有比较

孤立的数字没意义。**永远配比较基线**:
- 同比(去年同期)
- 环比(上月 / 上周)
- 目标值(业务定的 KPI)
- 行业基准(如果有)

❌ "本月营收 120 万"
✅ "本月营收 120 万,环比 +18%(上月 102 万),已超 100 万月度目标"

### 3. 不确定性公开

数据有局限,明说出来不丢人:
- 时间窗口短
- 样本量小
- 可能受到外部因素干扰
- 因果性 vs 相关性

## 写"发现"的范式

每个发现一个小节,固定三段式:

1. **结论**: 一句话观点(用粗体)
2. **证据**: 数字 + 图表
3. **含义**: 这意味着什么 / 怎么用

❌ 反例:
```
本月销售有所变化,各品类表现不一,需要进一步分析。
```

✅ 正例:
```
**美妆品类同比增长 35%,带动整体增长**

- 美妆贡献了本月营收增量的 70%(¥21 万 / ¥30 万)
- 服装、家电同比 -2% 和 +5%,基本持平
- 美妆增长主要来自新品 X,占品类销售 40%

**含义**: 资源应继续向美妆倾斜;新品 X 复购数据需要持续追踪
```

## 数字怎么写

- 钱:¥1.2 万 / ¥120 万,不要写 12000 / 1200000(可读性差)
- 百分比:精度到 1 位 — 35.2% 不是 35% 也不是 35.234%
- 大数:用千分位或 K/M — 1,234,567 → 123 万 或 1.2M
- 比较时单位一致:不要"涨 35%,即 12 万"(让读者算)→ "涨 35%(¥12 万)"

## 图表怎么贴

- 每个图必须有标题(说明图的中心信息,不是简单 "趋势图")
- 必须有清楚的轴标签和单位
- 图前后都要有解读 — **不要让读者自己看图想答案**

## 反模式

- ❌ "经过分析发现..."(废话开头,直接给结论)
- ❌ 一段里放 5 个数字让读者自己整合
- ❌ 只贴图不解读
- ❌ 把脚本 print 出来当报告(应该提炼)
- ❌ 用情绪化措辞("非常优秀"、"令人担忧")—— 给数据,情绪让读者自己产生
