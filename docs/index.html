Design Philosophy
AgentHub is designed to make multi-agent orchestration boringly reliable — 每一条通信路径都有明确的协议；每一个 Agent 都有隔离的上下文；每一次工具调用都经过 Hook 审计。 复杂性被封装在 Orchestrator 内部，用户看到的只是消息。
01 · Positioning
项目定位
不同于单 Agent 对话产品，AgentHub 的核心模型是一个分层 Agent 网络，以 IM 为交互界面驱动多 Agent 协同完成复杂任务。
🧠
Orchestrator 主 Agent
接收用户意图，负责任务理解、拆解与调度。不直接执行任务，而是通过 22 个内置工具驱动下层 Agent 并行运作，管理 blocked_by 依赖图、等待结果、汇总回复。
⚡
专属子 Agent
执行具体任务（写代码、查资料、审查代码等）。每个 Agent 有独立的 Thread、独立的 Adapter（Claude CLI / Codex / OpenAI 兼容接口），互相隔离，结果通过 wake_event 通知主 Agent。
💬
五种对话模式
单聊（直连子 Agent）、群聊（Orchestrator 主导）、broadcast（多 Agent 概率自决是否回复）、@个体（复用历史 Thread）、local_edit（代码文件编辑），覆盖不同协作场景。
🐳
沙箱 + 审批闭环
代码执行和应用部署运行在会话级 Docker 容器沙箱内，每个会话隔离。高风险操作走 ApprovalHook 审批闭环，asyncio 层面阻塞等待用户授权，结果可通过反向代理在前端 iframe 预览。

Orchestrator Agent Loop
八步循环驱动主 Agent 完成任务拆解、工具调用、错误恢复，支持 wake_event 子线程唤醒与上下文压缩。
💬
五种对话模式
单聊、群聊、@个体、broadcast（70% 概率自决）、local_edit，覆盖从个人助手到多 Agent 协同的全部场景。
🐳
Docker 沙箱 + 审批闭环
代码执行与应用部署运行在会话级隔离容器中，高风险操作通过 ApprovalHook 实时阻塞等待用户授权。
⚡
多 Agent 并行 Streaming
三级嵌套 streamingMap 支持群聊多气泡并发流式输出，Teams 风格实时显示每个 Agent 的回复进度。
🔧
核心工具集 · 22 个
任务调度、任务链、用户交互、上下文管理、文件沙箱、部署与网络七组工具，覆盖 Agent 所需全部能力。
🔄
Workflow 视图 + 历史回看
每轮快照落库，前端 WorkflowView 实时展示工具调用详情，支持历史轮次任意回看。
